# Protocol 协作协议

> 本文档是本项目 AI 协作的总协议：在**任何任务开始前**都必须遵循本节阅读顺序与产出纪律

## 1. 文档的设计约定

- `OBJECTS/*` 写各对象特点
- `STYLES/*` 按页面类型分组，写本组分区与专属行为（CSS 仅参考，不要完全照抄，前端代码需要专门强化）
- **出处唯一**：同一条数据规则只允许在**一处**权威描述，其余文档只能引用；冲突仲裁见 §5
- `Verify.md` 的规则表是**索引**，不是权威出处；权威出处永远是 `OBJECTS/*` 各文档原文
- 发现 "出处唯一" 被破坏、文档自相矛盾、或文档标注 "不要直接照抄" 时，按 §4 上报项处理

## 2. 阅读分层模型

| 层级 | 内容 | 时机 |
|---|---|---|
| **L0 常驻** | `CLAUDE.md`、`Protocol.md` | 保持在上下文中 |
| **L1 任务必读** | 按任务类型固定序列（§3） | 动手前完整读 |
| **L2 按需查询** | 需要的文档 | 实现中，用 Grep 定位，禁止整读未列文档 |
| **L3 样例与代码对照** | `data\` 对应样例、`engine\` 对应 Service、同类已实现页面 | 实现前必看，产出后核对 |

## 3. 任务必读序列

| 任务类型 | L1 必读序列 | 每份 "读什么" |
|---|---|---|
| **页面功能**（renderer 页面行为） | `Navigation.md` → 对应 `STYLES\<页面组>.md` → 涉及的 OBJECT 文档 → `Modularization.md` | 页面代号 / 入参 / 可跳转页；本页组分区与专属行为；页面编辑 / 查看对象的 JSON 格式、编辑方式、规则；页面功能模块归属（React 组件） |
| **页面样式** | `STYLES\Global.md` → 对应 `STYLES\<页面组>.md` | 全局基调、深浅色、类名约定；本页组各分区样式；注意"仅供参考，不要完全照抄"，需理解后重构 |
| **数据服务**（`engine\main\services\`） | `Modularization.md` → 对应 OBJECT 文档 → `OBJECTS\OOP.md` → `Verify.md` → `IPC.md` | 本地数据服务模块与 BaseService 约定；对象 JSON 格式、规则、示例、数据文件夹路径；对象分类；提交拦截与校验规则（写路径必须遵循）；服务注册契约 |
| **类型/契约**（`engine\types.ts` 等） | `OBJECTS\OOP.md` → `OBJECTS\ELEMENTS\Id.md` → 相关 OBJECT 文档 → `Modularization.md` | 对象分类；id 物化路径、对象代号、上下级关系；对象 JSON 格式与规则；TypeScript 模块归属 |
| **Bug 修复** | `Verify.md` → 涉及对象的 OBJECT 文档 → `Navigation.md` → `IPC.md` | 非法数据判定、修复队列、`data\logs\invalid.json` 格式；对象 JSON 格式与规则；相关页面与跳转；服务调用链 |

## 4. 产出前自检清单

**硬性项：**
- [ ] 涉及的数据字段逐一对照 OBJECT 文档与 `data\` 样例，无凭空字段
- [ ] 同步更新 `IPC.md`
- [ ] 新增页面时同步更新 `Navigation.md`的镜像；修改数据规则时，同步更新 `Verify.md` 索引表

**上报项（不得自行脑补）：**
- [ ] 发现文档自相矛盾，或文档内标注 "不要直接照抄" 或文档的设计缺口 → 在 `perfection\` 镜像写同名提案并等待决策
- [ ] 发现代码与文档不一致 → 视为 "代码未同步文档"，写提案说明

## 5. 冲突仲裁原则

- 权威顺序：**OBJECT 文档原文 > `Verify.md` 索引表 > `README.md` / 汇总类文档 > `engine\` 代码 > AI 的推断**
- 若仍有冲突，应该上报
- 若判定是文档过时，走提案流程（`perfection\`）

## 6. Context 预算策略

- 单任务 L1 必读有限；用 Read 的 limit/offset 只读所需小节
- 读完先把关键事实压缩为清单（字段、规则、service 方法）再进入实现
- L2 一律 Grep 定位，禁止整读未列文档
