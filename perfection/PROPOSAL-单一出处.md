# 提案：harness 冗余审计与「单一出处」结构优化

> 本文件是对 harness 整体结构的提案（跨文件，非单一同名可替换文件）。
> 依据 `Protocol.md` §1「出处唯一」：同一条数据规则只允许在一处权威描述，其余只能引用。

## 一、发现的冗余（每类信息在多处出现）

1. **对象类型代号** 三处重复：
   - `OBJECTS\ELEMENTS\Id.md` —— 对象类型代号表（Ch/Cg/Ds/Dc/Er/Ev/Og/Rm/Rg/Rl/Wd/Tg/Nt/Ne + 上级/下级）



3. **校验规则正文** 重复（超出 Verify.md 的索引职责）：
   - `Verify.md` §提交时拦截、§间接非法 列了详细规则正文，与各 OBJECT 文档规则重复
   - 但 `Protocol.md` §1 已声明 Verify.md 是「索引，非权威出处」
4. **Navigation.md 表格与图双重维护**：§3 页面清单表 与 §4 mermaid 图 是同一跳转信息，已发生 tg-view 漂移
5. **Navigation.md 规则重复**：§2 已写「页内选择不入栈」「id 自解码」，§6 又重复；且 §6「新建提交后的跳转」内嵌「此规则为建议新增，原文未定义」的非权威内容
6. **枚举公共规则重复**：「所有语言都是必需的键」×5、「allow 是必需的键」×2、「由用户注册…文件名 `XType_值.json`」×5

## 二、建议的「单一出处」分配（哪个文件讲清哪个信息）

| 信息 | 唯一权威出处 | 其余文档的做法 |
|---|---|---|
| 代号 → 数据文件夹映射 | `Structure.md` §数据目录 | 仅保留「代号→文件夹」一列，代号本身引用 Id.md |
| 页面代号（小写，ch/wd…） | `Navigation.md` §1 | 明确「由对象代号派生（小写），代号见 Id.md」，不再复述 14 个对象 |
| 语言集合（9 种）与默认值 | 新增 `OBJECTS\CONFIGS\Language.md`（或并入 Config.md） | ENUM 文档、Config、types 引用之 |
| 校验规则正文 | 各 `OBJECTS\*` 文档 | `Verify.md` 只保留工作流 + invalid.json 格式 + 指向权威出处的索引表 |
| 模块/技术栈明细 | `Modularization.md` | `Structure.md` 作索引，只留一行指针 |
| 页面跳转关系 | `Navigation.md` §3 表 | §4 mermaid 图标注「示意，非权威」，或删除 |
| 可注册枚举公共规则 | `OBJECTS\ENUMS\` 新增公共节（或在 OOP.md 的 ENUM 节） | 各枚举文档引用，不再各自重复 |

## 三、落地建议（按优先级）

- **P0（已决策、快）**：① 对象代号三处合一；③ Verify.md 精简为索引；⑦ 技术栈合一。
- **P1**：② 语言集合单一出处；⑥ 枚举公共规则抽取。
- **P2**：④⑤ Navigation 表格/图、规则去重（涉及语义，需你确认后再动）。
