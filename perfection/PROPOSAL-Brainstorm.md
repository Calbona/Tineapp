## 一、✅ 时间成为「一等公民」（时间滑钮）

- **目标**：每个实例查看页都有一个时间滑钮，拖动即可看到该实例在不同时间点下的信息。
- **范围**：所有含 `Piecewise` 数据的实例查看页（Character/Organization/Regime/Region/…），滑钮值 = 一个 `TimePoint`；各字段按该时间点取 piecewise 值渲染；无 piecewise 的字段不受影响。
- **落点**：
  - `Navigation.md` §3 —— 各实例查看页新增「时间滑钮」元素说明
  - `STYLES\` 或新 `ELEMENTS\` 文档 —— 时间滑钮组件（范围、刻度、与历法 unit 对齐、默认值）
  - 可能 `OBJECTS\CHRONOLOGIES\Chronology.md` —— 滑钮刻度取自当前实例所在 World 的 chronology
- **依赖**：需先确定历法单位 → 滑钮刻度的映射（历法项 4 暂缓，但此处只需「读取」不需要改历法）。
- **关联**：与 5（可视化联动）共用同一个时间滑钮值。

## 二、✅ 校验系统进阶（增量校验）

- **目标**：把「提交后全量校验」改为「增量校验」——用户改动某物后，只扫描必须扫描的集合。
- **范围**：建立「改动 → 依赖闭包」映射。例如：改 World 的 chronology → 扫描该 World 下所有实体的 span；改某枚举 → 扫描所有引用该枚举的实例；改某实体的 id → 扫描引用该 id 的所有关系/领土/元首。
- **落点**：`Verify.md` 整体改写 —— 校验流程从「全量」改为「增量 + 依赖闭包表」。
- **关联**：与 [PROPOSAL-单一出处.md](PROPOSAL-单一出处.md) 的冗余 ③（Verify.md 精简为索引）**合并处理**，一次改写 Verify.md，同时做到「去重 + 增量」。

## 三、✅ 数据迁移 → 导入导出系统

- **目标**：迁移服务扩大为完整导入导出系统。
- **范围**：
  - 导入 + 导出：列表编辑页；导出额外在实例查看页
  - 任意层级导入导出（World / 单对象 / 任意子树）
  - **id 冲突处理**：导入的数据 id 与现有 id 冲突时如何消解（重映射、跳过、覆盖，需明确策略）
- **落点**：
  - `Modularization.md` —— TransferService 职责扩为 Import/Export；新增 id 冲突策略说明
  - `Structure.md` §数据目录 —— 导入导出临时/落盘目录
  - `Navigation.md` —— 列表编辑页加「导入/导出」入口，实例查看页加「导出」入口
- **依赖**：依赖 7（类型精化）确定导出格式的数据结构；依赖增量校验（导出前/导入后校验）。

## 四、⏸ 历法系统潜力 —— 暂缓，无动作

## 五、✅ 可视化联动（星图淡入淡出 + N 跳）

- **目标**：星图中关系连线随时间滑钮所选时间做淡入淡出（过渡占比可配置）；点击另一实体丝滑将其挪到中心展示其星图。
- **范围**：
  - 连线淡入淡出：基于时间滑钮值，`span` 覆盖当前时间的连线不透明、否则淡出；过渡区间占比 = 可配置项
  - N 跳探索：从中心实体展开 N 跳关系（原有目标）
  - 重居中：点击实体 → 平滑平移到中心 → 展示其星图
- **落点**：
  - `View.md`（或视图文档）—— 星图时间淡入淡出规则、N 跳、重居中动画
  - `Config.md` —— 新增「过渡区间占比」可配置项
- **依赖**：依赖 1（时间滑钮提供所选时间值）。

## 六、⏸ 引用即链接 —— 暂缓，无动作

## 七、✅ 类型体系精化（代码直改）

- **目标**：精化 `engine/types.ts` 类型体系，使类型更贴合数据（原 Brainstorm：`EnumEntry` 按语义拆分、`Span` 判别联合等）。
- **范围**（待细化的具体项）：
  - `EnumEntry` 拆分：`EventTypeEntry`（单对象代号）vs `RelationshipTypeEntry`（`X=>Y` 对）
  - `Span` 判别联合（按 `type` 0/1/2/3 收窄 `end` 的语义）
  - 其他在审计中发现的类型与数据不一致处
- **落点**：`engine/types.ts`（**可直接改**，非 harness）；同步用 `types.probe.ts` 校验。
- **依赖**：是 2/3 的类型基础，建议先做。

## 八、✅ 体验工程（undo/redo + i18n）

- **目标**：提升基础体验。
- **范围**：
  - undo/redo（操作历史，覆盖新建/修改/删除）
  - i18n 补全（当前 `assets/languages/` 仅 zh_CN 有少量 key，其余 8 个语言文件为空）
- **落点**：
  - `Modularization.md` —— 历史栈/undo-redo 服务
  - `assets/languages/*.json` + `Config.md` —— i18n 文案与语言配置（半 harness）
- **依赖**：无强依赖，可独立推进。
